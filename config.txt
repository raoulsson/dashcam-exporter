# ============================================================================
# TRIP GROUPING
# ============================================================================
#
# The publishing unit is a "trip": a park-to-park unit anchored on where the car
# last parked (a configured home is an extra park target).
#   DEPART (drive away from the anchor) -> drive -> ARRIVE + PARK (return and
#   come to a stop). The departure and arrival are found by VIDEO ego-motion, so
#   they land on the real pull-out / pull-in, not on a GPS radius crossing.
# A stop ELSEWHERE (not the anchor) never closes a trip, so A -> B -> hang out
# ANY length of time -> A is ONE trip with the stop at B cut out. Between trips
# the car sits parked at the anchor; those idle clips belong to no trip. A
# ROLLOVER across trip_day_rollover:00 (04:00, not midnight) also force-closes,
# bounding a one-way relocation (drive to a base, sleep, drive back = two trips).
# Every interior stop becomes a 'Fast forwarding...' slide (no duration split).
# Video needs numpy + opencv; without them it falls back to the GPS radius.
#
# Each trip is written as trip_<day>_<HH-MM>_<idx> with a _meta.json sidecar
# carrying its day label, so a publishing UI can group a day's trips together.
#
# YOUR HOME. Set these two to where you park and you are done — a trip closes
# when the car comes back within home_radius_m of this point. Leave them unset
# and the exporter simply has no home anchor: trips still work, they just close
# on returning to wherever each one started.
#
# Zurich is here as a working example. Replace it with your own coordinates
# (right-click a spot in Google Maps -> the first entry is "lat, lon").
#home_lat = 47.3769
#home_lon = 8.5417
#
# PRIVACY, only if you care: this file is committed. If you plan to push your
# fork and would rather not publish where you live, put the same two values in
# a gitignored .env instead —
#     SET_HOME_LAT=47.3769
#     SET_HOME_LON=8.5417
# — and they override whatever is here. Nothing else is needed; .env always
# wins for the coordinates, precisely so a public file can hold an example.
#
# The RADIUS is not private, just a tuning knob like trip_return_m, so it stays
# here. Metres from home that still count as "at home". Default 100.
#home_radius_m = 100

# Return-to-anchor distance in metres. Back within this of where the trip
# started closes the trip. Default 100.
#trip_return_m = 100

# How far (metres) the car must travel from the anchor before a return can
# close the trip — stops it closing on the driveway. Default 150.
#trip_leave_m = 150

# Hour of day the trip/day label rolls over instead of midnight. A trip
# starting before this hour is labelled the previous date. Default 4 (04:00).
#trip_day_rollover = 4

# Minimum distance (metres) the noise-pruned GPS track must reach from the
# anchor for a group to count as a real trip. Closer clusters are near-home
# puttering or parking-mode motion events (and a single phantom GPS fix can't
# fake it — it's dropped as noise first) and are auto-skipped. Default 500.
#trip_min_m = 500

# THE DELETE GUARD. 8) Clean Workspace erases the original clips and the renders
# they produced, and what it can prove first depends on what is set here. (The
# card is not this item's business — that is 9) Delete SIM Data, with its own
# evidence and its own word.)
#
# THE RULE, in one sentence: the floors that never leave this machine first,
# and then the destination's answer decides.
#
# The floors: not one mp4 from this import exists, or the local render count is
# short or unreadable. Neither is delegated and no answer overrides them — an
# implementation that says yes to everything still cannot get an import that
# produced no renders erased.
#
# Then one question, asked of your uploader: is_complete(trip_ids) — are ALL of
# this import's trips at the destination? The trip ids come from THIS repo's
# reading of the import, off the sidecars, so a trip that was never encoded is
# in the list. You do not have it, the honest answer is NO, and its footage
# stays. That is what makes one all-or-nothing answer safe: asked "do you have
# everything you were given" you could truthfully say yes about a trip you were
# never given.
#
# THE ONE READING THAT MUST NEVER BE INVENTABLE is "could not find out". An
# uploader whose destination is unreachable says Evidence.UNKNOWN, and
# unreachable is not permission. Evidence.NA is a different thing entirely — it
# means the question does not ARISE here (an archive disk stores footage; it
# does not publish it) and it removes the gate rather than failing it. Getting
# those two the wrong way round is how footage gets erased on the strength of a
# check that never ran.
#
# With no website_uploader configured nothing can be verified: it says so in
# red, names the check that could not run, keeps the renders instead of purging
# them, and still makes you type CLEAN.
#
# When it DOES go ahead on your answer, the gate table and the banner name the
# implementation that gave it, and so does the recorded step. Not a safeguard —
# a trusted component needs none — but so that afterwards, when the footage is
# gone, whose answer it was is readable off the tool.
